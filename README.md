# sing-box 是什么、怎么用

sing-box 的客户端页把图形应用与配置资料分别组织，singbox、sing box 这些写法在本文对应同一阅读主题。SFA、SFI、SFM 是核对平台客户端时会遇到的名称，本文按官方渠道和配置对象解释，不把其他内核的格式直接搬来使用。

## 官方平台定位与图形应用分开阅读

sing-box 仓库 About 使用通用代理平台的定位。图形客户端页另写由 Project S 维护，提供统一体验和各平台功能；这两段说明不是把仓库与每个商店应用当成同一发布文件。平台定位、图形项目和分发渠道各有记录位置。

图形客户端列表将 Android、Apple 平台以及 Windows、Linux 分开。Android 是 sing-box for Android，Apple 一组覆盖 iOS、macOS、Apple tvOS，桌面一组对应 Windows、Linux。列表给出的平台组合不能由名称相近互相补写。

本页采用 [sing-box 官方文档](https://sing-box.sagernet.org/) 作为资料入口，[sing-box 官方发布页](https://github.com/SagerNet/sing-box/releases) 作为核心发布入口。一个用于查客户端及配置说明，另一个用于读取版本记录，不把核心标签自动当成所有图形应用的商店版本。没有给出的对应表继续留空。

资料里的许可证名称没有从页面侧栏直接读出，因此本文不为核心或图形应用写具体许可。About 的定位也不被扩写成效果结论。这里讨论怎样识别官方资料对象，不从开源项目名称推出每一发行版的条款。

## SFA 管理本地或远程的配置文件

Android 客户端页说明 SFA 用于管理、运行本地或远程 sing-box 配置。它确认的是配置文件这个对象，不等于应用提供远端配置内容。客户端接收输入与资源来自何处，需要各自资料回答。

页面给出的系统门槛为 Android 5.0 及以上。渠道包括 Play Store、Play Store Beta、GitHub Releases 和 F-Droid；这些是页面已经列出的分发类型，本文不添加安装地址或签名命令。普通渠道和 Beta 的标注不合并。

同页所述平台功能包括 TUN 透明代理。这个功能描述不能代替系统授权界面的原文，也不能凭一个功能名重建所有设备菜单。本文没有取得需要写入这里的统一点击路径，不把其他 Android 软件的步骤当成 SFA 的操作说明。

核对 Android 应用时，可以记录项目名、最低系统、页面列出的渠道与配置对象。它们都是该客户端页面明确给出的内容，不由核心的新版本号补到应用商店版号。没有实际取得的文件和运行结果，本文不写成完成状态。

## SFI 与 SFM 按 Apple 平台页的范围记录

Apple 客户端页使用 SFI、SFM、SFT 等名称，说明它们管理并运行本地或远程的 sing-box 配置。iOS、macOS、tvOS 的最低系统分别列出，不能把其中一个要求填给另外两个平台。名称所在的页面与每个安装文件仍需分别对应。

页面写 iOS 15.0 及以上、macOS 13.0 及以上、Apple tvOS 17.0 及以上。这些是客户端页的要求，不是所有基于同一核心的软件共同门槛。本文不将它们改写成任意 Apple 设备都可安装的承诺。

渠道中有 iOS、tvOS 的 App Store，Beta 的 TestFlight 又限定赞助者。macOS 还列独立版与 Homebrew Cask；不同渠道条件原样保留，不把“有 TestFlight”写成任何人都可取得该 Beta。本文不介绍账号注册、切换或购买。

GitHub Releases 一项也按平台分文件类型，不能把一个渠道标题当作同一包适配所有系统。这里仅记录分发范围，不提供特殊安装方式或权限处理。页面没有给出的教程步骤，继续不从其他项目补齐。

## 配置属于哪个项目，要先于形式比较

SFA 与 Apple 客户端的介绍都明确输入对象是 sing-box 配置。mihomo 的代理集合内容页则列 yaml、uri、base64，并对这些内容形式另作约束。后者说明的是 mihomo 代理集合，不能被摘出来给 sing-box 定义全部配置语法。

现有可用摘录没有提供足够正文，确认 sing-box 完整配置的格式定义。因此本文不在缺少依据时自行补写 JSON 与其他格式的转换规则，也不宣称两个项目能够直接读取彼此的完整文件。格式差别需要明确文档，不靠文件名记忆。

[mihomo 官方文档站](https://wiki.metacubex.one/) 在本文仅用于并读另一个项目的配置目录。它不是 sing-box 图形应用的官方配置教程，也没有替 SFA 或 SFM 承诺读入所有代理集合形式。来源并列不会改变文档原本的适用项目。

比较配置时，要将完整文件、协议条目、远程输入和界面管理对象分开。这里没有取得一份跨项目字段映射表，所以不提供逐项转换。本文可以确认两套项目各有文档入口，不能由这一点确认数据直接互通。

## 入站与出站列表不是同一份功能表

sing-box 入站导航包含 direct、mixed、socks、http、shadowsocks、vmess、trojan、hysteria、tuic、hysteria2、vless、anytls、tun 等名称。它们列在入站栏目，不能从列表抽出一个名字就当成订阅格式。目录存在也不代表所有图形客户端有同名按钮。

出站导航另列 direct、bridge、block、socks、http、shadowsocks、vmess、trojan、wireguard、hysteria、vless、tuic、hysteria2、anytls、ssh、selector、urltest 等名称。两表部分名字相同，栏目方向却不同。本文只用来解释资料组织，不扩写每一项协议的行为。

Endpoint 又是独立分类，导航包括 WireGuard、Tailscale、OpenConnect Client、OpenVPN Client/Server、MASQUE Client/Server。这些项目不能因也涉及网络连接，就全部塞回出站表。看到目录名称后，应保留所在栏目，避免把不同对象视为同义。

| 资料位置 | 这里确认什么 | 不由此扩写什么 |
| --- | --- | --- |
| 图形客户端页 | 平台应用和渠道 | 全部核心选项的界面覆盖 |
| 入站导航 | 入站主题名称 | 任意订阅内容形式 |
| 出站导航 | 出站主题名称 | 其他项目同名字段的含义 |
| Endpoint 导航 | 单独的端点分类 | 一份统一的协议清单 |

目录阅读与实际配置是两个层面。本文没有把所有标题改成“当前应用全部支持”，也没有用列表替代具体字段参考。

## alpha 标签、稳定状态与日期不能省略

截至 2026-10-23，官方页面显示发布源列出 1.15.0-alpha.12，以官方页面为准。alpha 标签表示预发布，不能删掉后只保留数字，或把它写成稳定版。核心发布源与图形应用的商店记录也不能混作一条。

现有两份记录对这条 alpha 的日期分别为 2026-10-09 和 2026-10-11，其中后一份取发布源 updated 字段。本文并列保留读数，不将差异解释成新的版本，也不替来源指定唯一时间。日期字段的来源必须跟在读数旁。

另有发布记录出现 1.14.3。该记录可以列出名称，但当前材料没有确认可用于这里的稳定版状态结论，因此不按版本外观选定稳定版本。稳定版与预览版的区分需要明确标注，不能由数字较小推断。

仓库页面未见归档标识，这也不是关于下一次发布的承诺。本文不根据版本日期评价维护节奏，不从某个发布源的首条记录推出所有渠道已经同步。所写时间点均限定为资料读取时。

## 从配置管理任务回到对应客户端文档

需要辨认 Android 渠道时，SFA 页能给平台门槛和分发类型；需要查看 Apple 平台时，另一页又给出不同系统及 Beta 条件。二者属于同一文档体系，也不要求分发步骤完全相同。本文没有为任何平台补统一安装路线。

配置输入需要确认它属于 sing-box，不将 mihomo 代理集合的三种内容形式直接称为 SFA 的完整格式。即便两份文档都列出某个协议名，字段结构、输入范围和应用管理方式仍没有在本文建立对应表。名字共享不等于文件通用。

图形客户端自身的版本记录也需要它的渠道资料。这里的核心发布号、最低操作系统、项目名称分别处于不同栏目，不能相互替换。没有取得应用商店版号时，本文不会拿核心 alpha 来补。

本页能确认的平台与渠道已写在各自小节，尚未确认的格式、许可证和稳定状态也明确留有边界。它们不是待由经验补齐的空格，而是本文资料没有覆盖的事项。后续有对应原文，才能增加带时点的记录。

客户端渠道还体现了同一名称下的适用条件。SFA 同时列 Play Store 与 Beta，Apple 页则区分商店、带赞助条件的 TestFlight，以及 macOS 的独立发行和 Homebrew Cask。渠道文字具体到平台，不能用一个 GitHub Releases 标题把全部系统的分发条件合并。

Windows、Linux 在图形客户端列表中归为 sing-box for Desktop，但当前摘录没有给本文它们的最低系统和安装包明细。本文不从 SFA 的 Android 门槛或 SFM 的 Mac 条件推算桌面另一平台的要求。列表存在与已取得完整安装规范不是同一步。

mihomo 集合资料可进一步显示配置对象的不同。type 的 http、file、inline 决定集合来源，url、path、payload 又各有条件；它们不是 SFA 页面列出的通用字段。本文用这组例子说明为什么不能借另一个内核的参数填入未知的完整文件。

同样，文件内容页对 URI、BASE64 是否需要 proxies 的说明，也只对应那一页的对象。即使客户端都能读远程资料，仍需要各自正文才可确认字段及形式。本文没有做转换，也不将这样的比较描述成已通过解析。

稳定状态缺少时，本文保留的是待核对项目，而不是断言不存在稳定版本。发布源中有 alpha，有其他编号，不能由此自行补一个稳定通道对应表。这里的资料限制只描述本页取得了什么，不评价项目。

出站导航中的 selector、urltest 在这里仍只当主题名称处理。本文没有从标题解释选择算法、检查间隔或默认行为，也不把它们当作图形应用已经展开的按钮；需要具体定义时，仍需对应正文。

## FAQ

### SFA 读的是谁的配置？

官方客户端页说管理并运行 sing-box 本地或远程配置。它没有因此承诺附带外部服务资源。

### Apple 平台的 Beta 是所有人都可取得的吗？

页面将 TestFlight Beta 限定赞助者。这个条件不能因为同页有 App Store 就省略。

### mihomo 的内容形式能直接当作 sing-box 格式吗？

那段资料描述的是 mihomo 代理集合。本文没有取得允许将两套完整配置直接等同的依据。

### 1.15.0-alpha.12 能写成稳定版吗？

alpha 标签需要保留。它是预发布记录，不由本文改为稳定状态。

### 同一协议在入站和出站出现，作用就相同吗？

目录中的位置和方向不同。本文只确认对应栏目存在，不据名称相同补字段含义。

### 核心版本就是 SFI 或 SFM 的商店版本吗？

没有取得这种对应表。核心、图形客户端与渠道记录在本文分开。

### Desktop 列表给出了 Windows 最低系统吗？

所用客户端列表只确认这类平台入口，没有给本文完整门槛。Android 和 Mac 页的版本不能借给 Windows，具体安装文件也没有在这里取得。本文不会由桌面这个分类补系统数字。

### 侧栏有 License 就可以写具体许可证吗？

当前页面没有直接取得许可名称。链接存在不等于正文已读，本文也没有按其他代理项目的条款补填。未知的是本文资料范围，不能据此说项目没有许可。
